## 3.1 n8n UI 界面概览

- **一键配置中文界面**  
  - 浏览器翻译：Chrome 选择“翻译为中文（简体）”。  
  - 沉浸式翻译插件：https://immersivetranslate.com/zh-Hans  

### 3.1.1 首页仪表盘 (Dashboard)

- **Overview（概览统计）**：默认最近 7 天数据。  
  - Prod. executions：已激活工作流成功运行次数。  
  - Failed prod. executions：已激活工作流失败次数。  
  - Failure rate：失败率，核心健康指标。  
  - Run time (avg.)：平均运行时间，过长需优化。  
- **Create Workflow**：醒目的创建按钮，直接进入空白画布。  
- **Workflows**：工作台，创建/删除/搜索/组织工作流。  
- **Credentials**：安全的凭据保险箱，API/OAuth 加密存储，下拉引用。  
- **Executions**：执行记录与调试，查看每次运行的输入输出。  

### 3.1.2 编辑器界面 (Editor)

- **中央画布 (Canvas)**：可视化构建区域，点击 “+” 添加节点并连接。  
- **Execute Workflow**：手动运行/测试当前工作流，便于调试。  
- **Active**：总开关，激活后触发器才监听事件。  
- **Save**：保存所有修改。  
- **+（添加节点）**：添加触发器或动作的主要入口。  

## 3.2 n8n 工作流运作的核心概念

### 3.2.1 工作流 (Workflow)
- 自动化任务的集合：1 个触发器 + 若干动作节点。

### 3.2.2 连接器 (Connection)
- 连接节点的数据“线”，决定数据流向（上游输出 → 下游输入）。

### 3.2.3 节点 (Node)
- 工作流的基本单元，分触发器与动作。  
  - **触发器 (Trigger)**：决定“何时”执行，且每个工作流仅一个激活触发器。  
    - 示例：Schedule 定时、Webhook 接收 POST、Gmail Trigger 收件。  
  - **行动器/动作 (Action)**：决定“做什么”。  
    - 示例：Google Sheets 读写表格；OpenAI 提问；HTTP Request 调用任意 API。  

### 3.2.4 数据流
- 数据如河流，从触发器开始，流经各节点被处理再向下传递，下游可访问上游所有输出。

### 3.2.5 节点生命周期
- Input → Processing → Output。  
  - Input：接收上游数据。  
  - Processing：按节点配置处理（如 Set 拼接字段）。  
  - Output：输出处理结果给下游。  

### 3.2.6 工作流执行方式
- 同步 vs 异步：Webhook 可同步返回响应，同时后台继续异步任务。  
- 串行 vs 并行：默认对数组逐条串行；可用子工作流等方式批量并行提高效率。  

## 3.3 理解 n8n 的数据结构

### 3.3.1 理解 JSON —— 数据流动的关键

在 n8n 中，所有数据都以 JSON 在节点间传递。典型 Item 结构：

  <div className="code-card__header">
    <span>JSON 示例</span>
    <span className="code-card__copy">复制后粘贴</span>
  </div>
  <pre><code>{
`{
  "json": {
    "field1": "value1",
    "customer": {
      "name": "Alice",
      "email": "alice@example.com"
    },
    "products": [
      { "id": "A1", "price": 100 },
      { "id": "B2", "price": 200 }
    ]
  },
  "binary": {
    // 用于存储文件等二进制数据
  }
}
`}
</code></pre>

- 核心概念：对象（{}）、数组（[]）、路径（如 `json.customer.name`，`json.products[1].price`）。  

### 2.3.2 理解表达式（Expressions）

- 语法：`{{ ... }}`  
- 基础：`{{ $json.key }}` 指向上一个节点输出的 json。  
- 进阶：`{{ $('节点名称').item.json.some_key }}` 跨节点精确取数。  

### 2.3.3 数据处理和清洗：Code 节点示例

当 LLM 输出的 JSON 不纯净时，用 Code 节点净化并解析：

<div className="code-card">
  <div className="code-card__header">
    <span>Code 节点示例</span>
    <span className="code-card__copy">复制后粘贴</span>
  </div>
  <pre><code>{
`// 1. 获取输入：从上一个AI节点获取可能不纯的输出字符串
// $json.output 会读取名为 'output' 的字段
const llmOutput = $json.output;

// 2. 净化数据：使用正则表达式，像用筛子一样找出真正的JSON部分
// 这行代码的意思是：“在这段文本里，找到从第一个'{'开始，到最后一个'}'结束的所有内容”
// 's' 标志让 . 可以匹配换行符，这对于处理多行JSON至关重要
const jsonMatch = llmOutput.match(/{.*}/s);

// 3. 安全检查：如果找不到'{...}'结构，就抛出错误，防止流程继续执行
if (!jsonMatch || jsonMatch.length === 0) {
  throw new Error("无法在输入中找到有效的JSON字符串。");
}

// 提取匹配到的纯净JSON字符串
const cleanJsonString = jsonMatch[0];
let parsedData;

// 4. 核心转换：将“文本”形态的JSON，转换为可操作的“对象”
// JSON.parse() 是JavaScript的核心功能，它将JSON字符串“激活”，变成我们可以用 .key 的方式访问的对象
try {
  parsedData = JSON.parse(cleanJsonString);
} catch (error) {
  // 如果解析失败（比如JSON格式本身有问题），也抛出错误
  throw new Error(\`JSON解析失败: \${error.message}.\`);
}

// 5. 输出结果：将处理好的、结构清晰的数据返回给下一个节点
// return { ... } 定义了这个代码节点的输出结构
// 下一个节点就可以用 {{ $json.Title }} 来轻松引用标题了
return {
  Title: parsedData.Title,
  Summary: parsedData.Summary,
  CoverImagePrompt: parsedData.CoverImagePrompt
};
`}
</code></pre>
</div>
